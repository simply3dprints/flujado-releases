Connector setup and test status



Connector guide for beta.18.11. Use the compatibility table for the exact scope of each prepared, software-tested or practically tested route. No route is fully Verified.

Install the official simulator, launch-monitor app and connector first. Verify their connection outside FluJado. Do not replace a working connector version solely because another flow uses a different version.

Select the exact supported profile in guided setup. Confirm detected executables and the simulator display. Connector configuration, simulator choice, ports and any required account login must match the selected route.

Prepared means a route exists. Software-tested means its logic passed isolated checks. Hardware-tested means actual shots were confirmed for that combination. The catalogue has 142 software-checked profiles; this does not mean 142 hardware-tested routes.

Previous practical tests include Muni and Drills with ProTee VX and Square Omni. Uneekor hardware confirmation, VTrack customer detection confirmation and other untested combinations remain separate open items.

Start, switch and close



Start the simulator through its card. Follow only the remaining prompts shown for your selected profile. Do not start a second connector manually while the route is still starting.

Built-in routes may close conflicting apps, start the connector and launch-monitor software in a required order, check readiness and bring the simulator to its assigned display. Preserve the tested order; for applicable rēlā/ProTee profiles the connector starts before ProTee Labs.

If the route cannot confirm a connection, read its message before continuing. A running process is not the same as Connected or Ready. A missing ball may delay readiness without indicating that the software connection failed.

Use the Hub’s existing stop/switch controls. Shared connectors and custom workflows may need different ownership rules, so a running-app badge is not a universal safe-close button. Confirm both shutdown and a return start when testing a new route.

Muni’s newer native launch-monitor menu is separate investigation work. Existing tested connector routes remain available; an announcement or community recipe alone does not replace a tested route.

Create or review a custom route



Use Flows & Help > Flow wizard for installed apps, launch order and conflict shutdown choices. Choose the simulator app and review the resulting plan. Save a draft if you are unsure.

The wizard cannot configure unknown connector buttons or ports. Keep its connection-confirmation step until you can verify the required connection yourself. A custom flow is untested until validated on the intended hardware.

ChatGPT flow exports a sanitised overview and prompt. Import the requested JSON, inspect the proposal and apply only supported actions. Importing does not change settings. Applying saves pending edits and creates a configuration recovery point.

Test startup, real shots, shutdown and any realistic simulator switch. Share a confirmed working flow and its exact tested combination on the community Discord. If it needs new connector support, report the missing action rather than executing an unknown script.

Record and report a connector issue



Use Record flow and explicitly choose All screens when the connector and simulator open on different displays. Choose a single Screen for readable detail, or a Window for a supported app. Nothing records automatically when this window opens.

All screens retains display positions and puts every connected display into one video. Text becomes smaller with more screens. Close private windows first. If the display layout changes or a screen disconnects, capture stops; refresh and choose again.

Start recording, select a new local AVI filename, move the controls away from the simulator display, reproduce the issue and stop. Review saved video plays the local file. Audio is always off. No automatic upload occurs. Limits are 2 minutes, 128 MB, 1280 x 720 and 8 fps.

For black or unsupported window capture, choose the relevant screen. A no-shot Muni/projector and rēlā/second-display recording was checked. Zero performance impact under all loads is not proven; do not treat this 8 fps support video as a frame-time measurement.

Include Hub version, simulator, connector version, launch monitor, expected action, actual status and reproducible steps. Review all attachments for keys, names and other private data before sharing.

Recover and validate



Keep a known-working configuration backup. Review restore proposals before applying them. A configuration backup does not include your licence and cannot restore every setting belonging to a third-party simulator.

If an update is interrupted, allow the updater to finish recovery before starting another installation. The candidate has isolated MSI update, registration, repair and rollback checks. Real client confirmation remains distinct from automated results.

For a route that fails before connection, check the installed executable, correct profile and competing connectors first. For a Connected-but-no-shot problem, check the monitor’s own readiness and ball detection. Keep the simulator’s existing settings intact while gathering evidence.

Button automation is specific to the supported connector and state. Moving a window is different from changing its layout or software version. Do not assume every text-labelled button is safe to click or that all versions have identical controls.

Never post private connector download links from restricted communities, licences or tester lists. Use official distribution channels and send only relevant, reviewed diagnostics.

Add Drills Web



Install rēlā and the correct device plugin first. Open https://web.drillsgolf.com/ and obtain the official Drills Web Bridge through the Drills dashboard. Extract the download to a permanent folder, then locate DrillsWebBridge.exe in the Hub. Do not launch from the zip or move its folder afterwards.

Open Menu > Settings > Setup wizard. Add Drills Web and choose the exact monitor profile: ProTee VX (Web Bridge + rēlā) or Square Omni (Web Bridge + rēlā). Leave Replace selected existing golf workflows off to preserve working routes. Check the detected browser, Web Bridge, rēlā and ProTee Labs where required; locate any missing executable.

Choose your simulator display or retain its saved choice. Save and open the Drills Web tile. The Hub opens its dedicated Edge/Chrome profile fullscreen on that display. Sign in yourself if prompted. Your regular browsing stays separate; the Hub does not copy passwords or cookies.

Choose your own game or practice mode. No range opens automatically. The screenshot shows the route selector. Locally shot-tested means real shots were confirmed for that specific route; it is not full Verified status. The compatibility evidence lists the exact test scope.

Connect, switch and troubleshoot



For the new VX route, complete the ProTee plugin setup in Socket Relay mode, local port 12321, with responses enabled. Labs GSPro Auto-connect must work; keep automatic GSPro game launch disabled. The Hub does not change Labs settings. Retain the existing desktop route if your plugin needs a different mode.

For Square Omni, use the appropriate rēlā plugin and Bluetooth connection. Close competing connectors for that device. The bridge receives from rēlā on TCP 921 and serves the browser locally on 5921. A matching Hub profile does not require you to edit those ports manually.

Switch using the desktop/Web Hub tiles. The Hub removes the conflicting receiver, starts the bridge before the connector and checks the actual connections. A Ready label alone does not prove shot delivery. Closing Web closes its dedicated browser, bridge and managed connector; regular browsing stays open. Shared ProTee Labs may remain open.

No ball appears? Check ball detection in the device software and your exact route first. Follow the Hub message for a busy port or missing plugin; do not start additional connectors alongside it. The supported VX route allows one graceful Labs recovery; an update or unknown state needs attention.

Report the Hub, Drills, bridge and connector versions, monitor, expected action, actual message and reproducible steps through FluJado support/test Discord or info@flujado.com. Attach only reviewed recordings or diagnostics. Never share licences, browser profiles, passwords or raw account data. Share a new working community flow only after a real test.
